# Simulate-12306-Ticket-Waiting-List-Module
模拟12306车票候补模块
#
一、项目要求
  
         旅客没买到票时，可以提交候补订单，系统按提交时间先后顺序排队。当有退票／放票产生余票时，系统从队头开始依次为候补用户分配车票，先候补先出票。每条候补订单信息：订单号、旅客姓名、身份证号。
         系统支持以下操作：
         1. 新增候补订单：将订单加入队列尾部（入队）。
         2. 余票发放：输入本次释放余票数量k，从队头依次处理候补订单：订单候补成功，订单出队，输出订单信息；剩余余票减去该订单所需票数，继续处理下一个。
         3. 余票为0时，判断候补队列是否为空，如不为空，继续等待，新增订单入队尾。
         4．退出程序。

二、设计思路

          1.数据结构选型分析
                候补业务具有严格顺序性：(1). 先提交的订单优先获得车票
                                      (2).有余票时从队头开始处理
                                      (3).未满足的订单需要继续排队等待
          2.结构体设计
                (1). 订单结构体 Order:存储每一条候补用户的完整信息(订单编号、旅客姓名、身份证号、所需车票数量)
                (2).循环队列结构体 Queue:订单数据数组（存储排队用户）、 队头指针 front（待处理订单位置）、 队尾指针 rear（新订单入队位置）
          3. 核心功能设计
                (1). 队列初始化:清空队列指针，创建空候补队列。
                (2). 候补订单入队:用户提交候补请求，从队尾入队，实现排队等待。
                (3). 余票自动分配逻辑:输入新增余票数量，从队头依次处理订单：
                                     余票充足：订单成功出票，订单出队
                                     余票不足：当前订单无法完成购票，保留在队列首位，本轮分配结束
                (4). 队列判空、判满:防止越界操作，保证系统稳定性。
           4. 整体业务流程
                (1). 用户新增候补订单，自动进入队列尾部排队
                (2). 系统录入新增余票数量，触发自动出票
                (3). 按排队顺序优先满足前排用户
                (4). 无法满足的订单继续等待下一轮放票
                (5). 循环执行，模拟真实 12306 候补机制
